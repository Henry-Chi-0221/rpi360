# Migrating to v2

Existing files are read-only inputs. Migration commands create new outputs and
refuse to overwrite existing destinations.

| v1 surface | v2 destination |
| --- | --- |
| Dual-track `.r360.mp4` | Web import, or `tools/migration/import_legacy.py` |
| Schema-1 calibration | `tools/migration/convert_calibration.py` |
| `Player.mp4`, `play`, `inspect` | Retained transition reader/CLI |
| `calibrate-*` | Retained Python calibration workflows |
| Camera recording | Headless camera service + device client |
| `rabbit-hole` | `inverted-tiny-planet`; old alias warns in compatibility code |
| Showcase writer | Native/browser export engine + `demos/recipes` |
| Public sample MP4s | `fixtures/legacy-recordings`, for regression only |
| Pi renderer/window | Optional legacy diagnosis; new capture is headless |

```sh
make core
uv run --all-packages python tools/migration/convert_calibration.py old.json new.json
uv run --all-packages python tools/migration/import_legacy.py old.r360.mp4 new.r360
uv run --all-packages python tools/migration/archive_recording.py new.r360 new.r360.zip
uv run --all-packages python tools/migration/recover_recording.py interrupted.r360 recovered.r360
```

The legacy reader preserves old compact calibration metadata. Conversion composes
the historical mount rotation explicitly and verifies media by decoding the
remuxed tracks. Missing source clock/exposure information stays unknown. The old
curated samples had already been retimed; conversion cannot recover their original
sensor timing. Use the original Pi recordings for demos, never those test fixtures.

Transition APIs will not be removed before v3. The v2 schemas and SDKs are the
application-development boundary. Prototype code is available in Git history and
the local pre-migration backup; it should not become a dependency of a new app.

`Player.mp4()` emits a deprecation warning. Its CPU viewer remains a reference
implementation for existing Python integrations; Web, worker exports and Apple
use the shared Rust/WGSL renderer. Production camera capture delegates to the new
capture engine. The injected-camera diagnostic adapter still accepts legacy raw
H.264 with a nominal frame rate; that adapter cannot recover missing timestamps
and must not be used for new recordings. The v2 camera service never uses it.
